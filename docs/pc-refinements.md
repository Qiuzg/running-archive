# PC 端优化记录

## 当前行为（2026-10-20 整理）

- 首页移除搜索、距离筛选和筛选叠图，每批显示 20 条路线。
- 首页与比赛使用预生成 SVG 缩略图；路线集读取预计算快照。点击记录仍按需加载完整路线。
- App 同步后后台合并生成图片和路线集，失败自动重试；每日 04:00 兜底更新。
- 可见网页每 15 秒检查数据版本，记录、首页汇总、统计与比赛列表一起更新；快照每分钟检查。
- 顶部 App 直接进入开发历程，功能展示通过二级导航进入。全站导航位置统一，背景与地图或文档自然衔接。
- 修复城市匹配、侧栏比例、跨页面返回时地图漂移，以及轨迹预览过度简化的问题。

部署运行以 [快照与自动更新运维说明](live-updates.md) 为准。以下保留实现过程；早期筛选、96 点预览和仅每日更新方案已被后续版本替代，历史耗时不代表当前性能保证。

## 初期调整

按使用反馈移除首页新增的关键词、城市和月份搜索区，保留距离分类、筛选叠图与列表分页。路线、路线集、比赛、统计、App 共用 `src/site-navigation.css`：统一按钮、字体、头像、栏高和容器宽度，固定在顶部，并预留滚动条空间。App 页同步使用全站导航，功能和开发手记仍可从正文进入。

开发手记已根据后续提供的大纲整理为 `journal.html` 图文文档，App 展示页保留文章入口。

## 首轮实现（搜索区已按上述反馈移除）

- 路线：名称、城市和日期关键词搜索，可与城市、月份、日常/长距离/比赛组合筛选，支持重置、结果计数、分批加载与筛选叠图。日常覆盖所有非比赛且不足 16 km 的路线，修复不足 8 km 被漏掉的问题。
- 导航：“汇总”更名“路线集”。地图页桌面侧栏加宽至 410px；统计页使用最高 1280px 的独立宽布局，兼容深浅主题和窄屏。
- 年度回顾：年度里程、同比、跑步天数、最长距离，以及本年/上年月度对比柱图。当前年比较截至当天的相同日期范围，历史年比较全年；闰日对齐上年 2 月末。上年无里程时显示“暂无可比基线”。
- 月度回顾：周一开始的日历、每日累计公里、同日多条记录、月份/日期筛选和路线详情入口。刷新、分享 hash 链接和浏览器返回均保留年月日。
- PB：5 km、10 km、半马、全马四类整次活动 PB 及首次记录/每次提升。筛选距离达到目标且不超过目标 3% 的有效用时活动，不进行距离折算；不是官方比赛或最快分段成绩。详情中公开计算口径。
- 加载：逐资源记录状态，失败时显示可重试提示；只重试失败接口，保留成功数据。列表 404、204、非数组响应均不再误当成空记录；每个请求有 15 秒超时。相关数据未完整就绪时，汇总显示“—”，统计和完整路线列表暂缓显示；不相关模块可以继续使用。重试后更新地图城市图层。
- 本地预览：API 代理随 `BASE_PATH` 同步处理 `/run/` 前缀，正式构建的子目录预览也能连接本地 API。
- 修复：比赛与对应训练去重；统计年/月更新顺序；路线 hash 被覆盖；地图尚未就绪时的路线选择；键盘焦点在月/日切换后保留。

## 统计边界

所有统计基于已导入记录。有效日期且不晚于今天的活动参与年度/月度/PB 计算。未同步日期不等于没有跑步。日历同日多次跑步合并距离，天数按唯一日期计数。

本轮验证数据库由仓库现有生成数据在本地建立（原先无本地数据库）：313 条路线、11 场比赛、333 条日常训练。没有修改源数据或线上数据库。

## 首页加载与比赛地图定位（2026-10-19）

- 首页路线列表请求 `preview_points=96`，在服务端保留主要转折点并限制预览点数；选中路线后取回原有预览，地图与图表共享正在进行的详情请求。默认列表接口、详情接口和数据库原始坐标不变。
- 预览缓存最多保留 768 项，以坐标内容和点数上限为键，坐标更新后自动重新计算。两个生产 worker 各自缓存。
- 各接口完成后逐步更新可用记录与汇总，地图 SDK 与数据请求并行加载。导航头像改用已有的 4.6KB JPEG，避免首屏下载 1.4MB PNG。
- 线上路线接口压缩传输从 1,470,287 字节降到 139,809 字节；原请求实测 3.63–3.67 秒，新接口缓存建立后连续请求约 0.70–0.90 秒，冷请求约 1.5 秒。以上是当前网络下的接口耗时，不是整个页面的加载时间保证。
- 从统计、路线集返回地图页面时，先恢复布局与滚动位置，再于下一帧更新地图尺寸并恢复视野。取消遗留的定位帧，高德使用立即定位，Leaflet 更新尺寸时不自动平移，避免旧尺寸和动画造成漂移。
- 12 项网页检查和 4 项预览算法检查通过；线上验证统计→比赛、路线集滚动→比赛，地图顶边与页面滚动均回到 0。
- 本次只发布前端与 routes.py、route_preview.py；生产 API 原文件已备份至 `/opt/running-archive/web-backups/20261019-preview-api`，未执行数据迁移。本地原有 5173/8000 服务保持运行。

## 高精度轨迹分批加载（2026-10-19 后续修订）

前一版的 96 点预览会丢失弯道细节。本次改为轻量目录与按需坐标批次：

- `/api/routes?preview_points=0` 仅返回路线信息，不读取轨迹列。完整目录保留日期关联、距离筛选和总数。
- 前端路线页初始 20 条，每次“再显示”追加 20 条；请求通过重复的 `route_ids` 参数指定记录，`preview_points=1200` 从完整轨迹生成预览，不对旧 300 点预览再次降采样。
- 单批最多 20 条，前端最多同时请求两批，已完成或正在请求的记录不重复下载。失败批次保留重试入口；返回空轨迹是完成状态，不无限重试。
- 坐标保留 6 位小数；服务端内容缓存上限改为 64 条。选中路线后读取完整坐标，详情缓存保留最近 8 条，供地图及图表共享。
- 比赛页只加载该页比赛，路线集和筛选叠图按需分批获取所需路线。城市行政区域直接匹配边界，不等待轨迹批次。保留原有 API 默认行为及数据库内容。
- 修正 SVG 横向/纵向直线路线的零跨度处理，缩小预览起终点标记，避免遮盖轨迹。
- 线上验证：342 条目录约 7,898 字节，首批 20 条共 24,000 点，压缩后约 117,662 字节。17 项网页检查和 4 项预览算法检查通过。
- 5 月 14 日路线按 96 点、1200 点、原始 1387 点对照：长折返在原始数据中存在，1200 点恢复更多曲线细节。对比图存于忽略目录 share-output/2026-10-19-loading-fix/preview-comparison.png。
- 原本地 8000 服务保留；新版测试 API 运行于 8002，5173 通过忽略的 .env.local 中 RUNNING_API_TARGET 接入。未配置此变量时仍默认使用 8000。


### 路线集每日快照（2026-10-19）

路线集单独读取 `/generated/atlas.json`，不再依赖实时路线预览批次。服务器从只读数据库事务中筛选超过 10km 的真实轨迹、去重、使用最多 1200 个点等比投影，预计算 SVG 折线与统计元数据；前端只组装已有折线，保留响应式布局与主题颜色。页面显示快照时间，页面内缓存五分钟后重新校验文件。

服务器 systemd `running-archive-atlas.timer` 每天 Asia/Shanghai 04:00 执行 `running-archive-atlas.service`；Persistent=true 补跑关机时错过的任务。首次上线立即生成。生成采用临时文件加原子替换，失败保留旧快照。首页路线与详情仍按原方式加载。部署静态目录时必须排除 `generated/`，避免用本地旧数据库快照覆盖服务器数据；标准 deploy.sh 已处理并安装定时任务。

手动更新：在 `/opt/running-archive` 执行 `systemctl start running-archive-atlas.service`。
本地生成：`python3 -m server.build_atlas --output assets/generated/atlas.json`。该目录不提交 Git。

验证：17 项前端测试、3 项快照测试通过；生产首份快照 71 条路线，1143km，页面与定时任务已核对，下次运行 2026-10-20 04:00 CST。本地服务保持运行。

### 首页静态缩略图与简化列表（2026-10-19）

首页左侧取消距离分类及筛选叠图控件，保留每批 20 条、继续显示和点击路线详情。缩略图改读 `generated/thumbnails.json` 清单和独立 SVG 文件，不再为首页列表调用 1200 点预览接口；前 8 张优先加载，后续图片浏览器懒加载。SVG 使用 180×140 等比投影、最多 1200 个点、起终点标记，内容哈希命名，重复访问可复用图片缓存。

`server.build_thumbnails` 已加入现有每日 04:00 systemd 服务（路线集后执行）。先写完全部图片再原子发布清单，旧图保留供已打开网页使用。新同步记录的详情可立即打开，尚未生成的缩略图显示“待每日更新”。失败提供重试，不回退到实时逐条计算。首页清单在本次页面会话中复用，刷新页面可读取新版本。

本地生成：`python3 -m server.build_thumbnails --output assets/generated/thumbnails.json`。生产首次生成直接读取服务器数据库；部署不上传本地 generated 目录。验证通过 17 项前端测试、3 项路线集快照测试、2 项 SVG 测试与生产构建。

### 同步后自动更新、导航融合（2026-10-19）

HealthKit 同步事务成功提交后，API 在 `server/snapshot-queue/` 写入独立通知文件。systemd path 监听非空目录并启动快照服务，等待 10 秒合并连续请求，依次生成路线集和首页 SVG 清单；仅成功后删除本轮捕获的通知。生成期间新到达的通知留待下一轮，失败则保留通知并间隔 60 秒重试。每日 04:00 定时任务继续兜底。API 不需要写静态目录或调用特权命令，队列目录归 www-data；同步响应不等待生成完成。

前台正在显示首页或路线集时，每分钟重新校验快照（后台页面暂停检查）；首页已有记录的图片会更新，新记录列表仍在页面重新读取基础数据后显示。路线集更新时间文案改为“同步后自动更新”。导航采用地图上方的透明渐变，文档使用对应页面纸色，保持原有统一导航位置。

验证：两项队列测试覆盖生成期间到达的新通知不丢失、生成失败保留通知；17 项前端测试和构建通过。生产以 API 用户写入同一通知函数验证触发链路，不新增虚假运动数据；2026-10-19 20:08:46 启动，20:09:16 成功完成，342 条缩略图，队列为空，API 健康。本地服务未停止。


### 跑步记录、统计和比赛自动更新（2026-10-19）

`/api/health` 增加 SQLite 主文件及 WAL 的轻量版本标识。网页可见时每 15 秒检查，有变化才获取完整跑步、比赛、路线目录和城市数据；全部请求成功且前后版本一致时一次替换状态并重建统计。失败保留原状态，下一轮重试；请求合并防止重入。保留当前年月、展开数量及侧栏滚动位置，不重建地图或改变视角。回到网页或网络恢复时立即检查。缩略图和路线集仍每分钟检查后台生成结果。

比赛页也使用 `generated/thumbnails.json` 和静态 SVG，取消实时预览坐标请求，保留照片优先、懒加载和点击完整路线。缩略图“待每日更新”文案改为“正在生成”。

18 项前端测试通过，新增测试覆盖失败保留旧数据、并发合并、相同版本不拉取列表及变化中的版本不发布。生产 HTML 与 21 项资源校验通过，比赛静态图片已在浏览器验证。本地新版 API 运行于 8003，Vite 5173 代理已切换，原服务保持运行。
